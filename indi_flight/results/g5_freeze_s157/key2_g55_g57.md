## Disagreements

None in any metric (59/59 within tolerance). Verdict: 27/28 same. The one difference is `o1_lemniscate_s1_pid`:
key2 FAIL (horizontal RMS 0.785 m > 0.5), key1 INVALID because its validity rule "indi_pos_status not logged" fires (the run is
pid_default, a reference, not an INDI flight). The numbers agree (key1 0.7851 / 0.0884, key2 0.7850 / 0.0885). The spec text
(GATES lines 224-260, 440-470) has no such validity rule, so key2 does not apply it; this is a scope difference, not a metric one.

## Readings of ambiguous text (key2)

- Analytic reference = `run.json hold_pos_ned` + trajectory offset at phase(t - t0), t0 = `trajectory.t0_us`, phase/shape rebuilt from
  the scenario definition (`run_scenario.traj_phase/traj_pos`, parameters from run.json). Cross-check against the sent `send_pva` rows in
  sends.csv: max |sent - analytic| <= 0.4 mm for all 7 o-scenarios seed 1, so the time alignment is exact.
- "Over the trajectory segments" = the `traj` segment only [t0, t0 + dur_s], not settle or hold. Horizontal RMS = RMS of the 2-D distance
  sqrt(ex^2 + ey^2), time-averaged on the truth 800 Hz samples.
- offb_vel_step: step end = `vhold` event time; last 3 s = [t_hold - 3, t_hold); |vx| at the end of the hold = interpolated truth vx at
  vhold + 4 s; dz = truth z minus the mean z over the 1 s before the step start, max over [step start, hold end]. vx is local NED north
  (send_vel type mask frame LOCAL_NED).
- LOC (G5.5): tilt > 60 deg for > 0.2 s, height below window start by > 2 m, NaN, horizontal distance to the analytic reference > 5 m
  (not applied to offb_vel_step: the reference moves 10 m by design). Ground contact and controller fault flag not checked.
- G5.7: edges = vehicle_status nav_state changes in [window start, window end + 1 s], order checked against the spec list. Edge speed =
  interpolated truth horizontal speed at the edge time. Thrust = -xyz[2] of vehicle_thrust_setpoint, hover = run.json hover_thr_used.
  Attitude error: truth body z vs q_d body z (setpoint held zero-order). Validity uses the AMENDED `leaveP` rule (4 edges leaving
  posctl >= 1.5 m/s). LOC for G5.7: tilt, height drop, NaN, disarm in window (no excursion rule: reference moves).
- Note: before the key2 numbers were final I viewed the first line of `mode_switch10_s1.check.txt` (key1) by accident. It was
  not used to change key2, which was already complete and unchanged afterwards; the rest of key1 was read only after the key2 runs.
