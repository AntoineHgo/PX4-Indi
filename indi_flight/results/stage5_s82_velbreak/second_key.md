Read-only review against indi_flight/design/brief_velbreak_s82.md. No build, no flight, no unit test run.

- NOTE src/modules/mc_indi_pos_control/McIndiPosControl.cpp:181-191,209-213: d is added on the NED axis `inject_axis` (AX 1/2/3 maps to index 0/1/2), u = c + d is `in.a_ref`, and c, d, u are published from the same cycle (a_c = out.a_c = a_ref, a_c_pre_inject = c, inject = d). The library takes `a_ref` only (indi_accel_control.cpp:235-275, a_c = a_ref when accel_only), so every state the law feeds back (jerk difference history at :138-162, t_c = t_f + a_c - a_f) is computed from u. A single clean break holds. Verified by reading; not run.
- NOTE McIndiPosControl.cpp:182-187: AX = 0 gives axis() = -1, so `update` is not called and inject stays an exact zero vector. Default AX 0 in the yaml. `setParameters` returns early when nothing changed (IndiPosInjection.cpp:40-44), so there is no state change when off.
- NOTE Sign and convention: pinj_csv.py:7-8,25-26 uses x = a_c (u), y = a_c_pre_inject (c), d = inject, and L = -G_yd/G_xd as in margins_est.py:7-11 and m3a_csv.py. This is the same as the task statement (L = -x/y in the loop sense). Window = first to last nonzero d, anchored to the injection log, not wall time. Verified by reading.
- NOTE Frequencies: I recomputed IndiPosInjection.cpp:54-67 with float32 parameters against margins_est.log_bins for 5 (Tp, fmin, fmax) sets, including the defaults and the pretest set. The bins are identical in all five. The phases (cpp:71-79) match margins_est.multisine. The unit test hard-codes values from margins_est (IndiPosInjectionTest.cpp:48-51), so a phase or sign error would fail it.
- MINOR McIndiPosControl.cpp:186 with IndiPosInjection.cpp:121-124: the `!armed` reset (`_started = false`) cannot be reached in the module. `update` is only called inside `if (can_run)`, and want_indi requires flag_armed, so `_started` stays true across disarm and re-arm. A second flight in the same boot, with no PINJ parameter change, reuses the old origin and the window is already over, so no injection occurs. This fails safe (d = 0) but defeats the "new flight restarts" comment. SITL runs one flight per process, so no effect on the pretest. Fix: call `update` or a reset hook every cycle outside can_run, or reset when !armed in the caller.
- MINOR Same location: the clock runs on `now` whenever the stage runs, and the stage can pause (can_run false, mode switch, stale att/acc). In that case the multisine continues unseen and unlogged, because the status is published only when `_indi.update` succeeds. The window then has a gap and the period count is consumed. frf_periodic with t uses the non-uniform LS path only if the grid is non-uniform, but a long gap would still corrupt a period. The pinj log should be checked for gaps in the window. NOTE-level for the hover pretest (not verified in the log).
- MINOR mc_indi_pos_control_params.yaml (MC_INDI_PINJ_AX long): this is a `|-` block wrapped mid-sentence, and it uses "u = c + d" and "c, d" as symbols. `.github/instructions/parameters.instructions.md` (applyTo src/**) asks for one paragraph in a plain scalar, plain words, and no restatement. "the acceleration is then unchanged" and the wrapping should be tightened. Names are at most 15 characters, which is fine. control.instructions.md also matches by path, but I did not read it for this review (only parameters.instructions.md was read).
- NOTE Timestamps: pinj_csv.py:21 uses `indi_pos_status.timestamp`, which is hrt_absolute_time() at publish (McIndiPosControl.cpp:211). The injector clock uses the cycle `now` (:186). The message has no timestamp_sample. The offset is a per-cycle latency of microseconds with some jitter. It cancels in L, because D, X and Y are all fitted against the same t, but it adds small phase noise at 8 Hz. Not mixed with any other time base.

Nothing tests the McIndiPosControl wiring (c/d/u logging, axis mapping). The brief's "checked to fail once when broken" is not evidenced in the commit. I did not look for it elsewhere.
