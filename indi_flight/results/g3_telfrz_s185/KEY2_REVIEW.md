2. OK .cpp:253 esc_errorcount is not touched while frozen; timestamp set at :237; value is `_erpm_last_rpm[i]` = last decoded value (held, bit-identical). Truth instance (:296-302) unaffected.
3. MINOR .cpp:249-253 RNG/delay line while a bit is set: the delay line keeps being written/read every frame (:264-265), so un-freezing returns to the current delayed truth with no glitch. uniformRandom() is NOT drawn for a frozen motor (same as for a `lost` motor, short-circuit), so with SIM_GZ_ERPM_DRP > 0 the drop stream shifts after the window versus a no-freeze run of the same seed. Only matters if the campaign compares a freeze run to its no-freeze twin on the drop pattern; same limitation already exists for tel_loss. FRZ=0 runs are bit-identical to before.
4. MINOR .cpp:249: frozen wins over loss on the same motor: during an overlap the error count does not increment (loss is masked), and the last_rpm held. Consistent with "valid frames" but means a same-motor overlapped loss+frozen draw does not exercise the loss path for the overlap. Document or accept.

OK run_scenario.py timed_windows (~551-565) + main loop (~1326-1334): each change carries its own param, so writing FRZ never touches LOSS and vice versa (different params; bit = 1<<motor for each). Same-motor and different-motor overlap both fine; sub-runs sum to dur (my reading and test). Off sorted before on at equal t (key (tc,0/1)). erpm_loss behaviour: same on/off times and on_us/off_us. MINOR: sub-run labels changed (`pre` -> `pre_erpm_loss`, `post` unchanged, new `between`); only matters if something parses `scenario:<seg>:pre`. Final FRZ=0 reset after the scenario (~1348) is unconditional, fine.

OK/MAJOR-free detector fit (IndiMeasuredTorque.cpp:127-140, 190-193): detector flags a motor when rpm is bit-identical for MC_INDI_ERPM_FRZ (0.5 s) while armed AND command varied > 0.02 in the window; any bit change or error-count change restarts.
