# K110 fixes, second-key review (S111), commit b0486b703e

Read-only review. Mutations in a temp copy only. Author log not read before writing this.

## Findings

### MAJOR
- **F-1 run_scenario.py hook logic has no test** (`run_scenario.py:983-996` timed eRPM loss, `:926-945` per-motor scale product and sqrt on EC MIN/MAX). Mutations in a temp copy that survived all five related test files: loss motor index `^1` (M3), post segment duration `dur - t_on` instead of `dur - t_on - t_len` (M4), `cum_scale *=` replaced by `=` so weak x saturation no longer multiplies (M5), sqrt dropped from the EC scaling (M6). The commit message says "tests for the three surviving mutations", but only the override/argv builders are tested (g3_run, scenario_overrides), not the runner's timing or the product. The code reads correct (below); the cure is to factor the sub-run plan and the new_all computation into pure functions and test them.
- **F-2 Wind velocity read is cross-thread and not deterministic** (`disturbance.py:331-343,360`). `on_pose` and `on_clock` are separate gz-transport callbacks (different threads). `pv.vel` is the last difference seen when the clock tick arrives, so the lag is 0..1 pose periods, depending on thread scheduling. The same seed can give a slightly different wrench series. The class docstring (`:157`) says "deterministic in the sample times", which holds for PoseVelocity itself and not for its use here. The effect is small (drag change over a few ms) but it is a determinism hole for a gate that is meant to be reproducible. Cure: compute the velocity from the pose stamp nearest below the clock stamp, or log the stamp of the velocity used (add vel_t to disturbance.csv) so the lag is measurable. Also `min_dt=0.004` with float stamps: if pose/info runs at 250 Hz, `t - last >= 0.004` can fail by one ulp and give alternating 4 and 8 ms differences (noise, not bias).

### MINOR
- **F-3 vel None falls back silently to the legacy non-air-relative force** (`disturbance.py:134,360-361`). Only counted and printed at exit. If the pose subscription never delivers (wrong topic name, model name mismatch `p.name == a.model`), every gust runs with the old pure force and the run stays labelled as air-relative. Pose is unflown (the commit admits it). Cure: fail or flag in run.json when `vel_none` > 0 after onset.
- **F-4 set_param latency lengthens the segment and shifts the loss window** (`run_scenario.py:986-996`). Each `sim.set_param` is a blocking CLI call during which sim time keeps running (the code itself records event_us vs event_done_us). The three sub-runs measure only their own durations, so the segment is longer than `dur` by about 2 x the call latency (ms to 100 ms at speed 1), the loss starts at t_on + L and lasts t_len + L, and all later segment times move. Cure: run each sub-run to an absolute target (t_seg0 + t_on, + t_len, + dur), not to a relative duration. Offsets are logged as on_us/off_us, so it is visible after the fact.
- **F-5 Stale sampler doc** (`g3_sample.py:293-294`): `timeline.note` still says "event offsets are seconds after the hold segment starts", contradicting `:53` and the unit strings (anchor = main-segment start). A reader of the JSON gets the old anchor.
- **F-6 Wind dir frame is unchecked in the test** (`g3_sample.py:207`, dir uniform 0..360 deg; `disturbance.py:138`). gz world is ENU and the formula is in the world frame, so w and v share the frame as long as pose/info is the world pose (it is). The run is consistent. It is worth one line in the doc that dir_deg is measured in the gz ENU world (0 = +x = east), not PX4 NED.

## Checks that pass

Wrench is a world-frame force with torque `r x f` about the CoM at `(0,0,cop_z)`; unchanged from before. vel None is handled (legacy force) and counted.

Validation rejects windows that exceed the scenario (`scenario_overrides.py:119`). Anchor segment = `loss["start"]` = main_seg (g3_run). Correct by reading, not by test (F-1). meta only reports fmotors[0] in the top-level `applied`, the full set is in applied_all (MINOR cosmetic). MIN is scaled by the same sqrt, so a non-zero idle MIN drops with the fault (pre-existing).
4. Anchor: g3_run puts weak, saturation and loss on main_seg and the timed loss relative to it. Doc contradiction: F-5.
5. Tests: all 24 files in tests/ run. Note that these scripts always exit 0 (print FAIL), so a loop on exit codes proves nothing; I grepped for FAIL/Traceback: none.
