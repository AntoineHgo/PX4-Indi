## Findings

1. No sizing defect found in the commit. All mass, inertia, drag, lever and torque numbers agree with
   my independent calculation for both airframes (x500 values are unchanged from before the commit:
   X500_MASS_KG = 2.064308 kg, same as the SDF).
2. Pre-existing, not introduced by 1e526e3845: the profile ends are not returned to zero.
   `wind_speed` (and `wind_diag`) hold the last wind after the gust (`disturbance.py:64`
   in the pre-commit file, same hold line now), and payload_add / com_shift hold to the end
   and are cleared as a step. This is a step to zero at `dur`, not a ramp. Behaviour is unchanged
   by this commit, so I do not count it as a defect here, but it should be known for the H2/H3
   analysis (the post-gust tail is 0.33 N on x500 and 0.07 N on quad5in).
3. UNVERIFIED: quad5in CdA = 0.012 m^2 and cop_z = 0.02 m are assumptions (the code comment says so,
   `disturbance.py` AIRFRAMES block). I did not check them against any measured source. Mass and
   inertia are from the SDF and are verified. The gust_x and gust_diag quad5in numbers scale linearly
   with CdA, and the torque from gust scales with cop_z.
4. UNVERIFIED: the TQ_STEPS comment cites the INDI G1 authority (1757 x 1.4e-3 = 2.5 N m, 205 x 2.7e-3 =
   0.55 N m). I did not check the G1 gains; I only verified that TQ_STEPS are the quad5in
   reference values and the scaling is by I/I_ref.
5. Container path: the SDF is read via a relative path from the bench directory (`..`/`..` to the
   repo root for x500, `..`/`sim` for quad5in). If the container mount differs, the fallback constants
   are used. I verified the fallbacks equal the SDF values, so the result is the same either way.
   Whether the container actually uses the fallback is UNVERIFIED (no container run).

## Verdict

**AGREE** on the sizing: mass, inertia, drag, lever, torque_steps scaling direction, airframe selection, fallbacks and sign
conventions all match my own numbers. No code defect introduced by 1e526e3845.

Items to fix in the note (not the code): gust_x 3 m/s force (0.066 N, not 0.10 N), gust_x peak time (12.5 s), gust_diag peak
direction (96.8 deg), the expectation that every profile returns to 0 at its end, and the "Ty" label in the old com_shift column.

Dead constant: `X500_MASS_KG` (`disturbance.py:49`) is not used by any profile now (the profiles read `af.mass`), kept as "reference only".
Harmless; remove or keep as documentation.
