# Reference airframe: sourced physical data (generic 5-inch FPV quad, ~610 g, 4S)

Purpose: single traceable parameter table for the INDI flight-control simulations.
Conventions: SI units; body frame FRD (x forward, y right, z down) as in PX4. Motor numbering as PX4 quad-X
(M1 front-right CCW, M2 rear-left CCW, M3 front-left CW, M4 rear-right CW). Thrust model T = kT*w^2, reaction torque Q = kQ*w^2.
Tags: **SOURCED** = value read directly; **DERIVED** = computed from sourced data (method given); **ASSUMED** = no public source found, reasoning given.
Session date 2026-11-15; no value below was taken from `indi_project/`.

## 0. Reference platform summary

Chosen config: 4S LiPo (nominal 14.8 V), 2207-class ~2400 KV motor (12N14P), 5.1x4.8-in 3-blade prop (Azure SFP5148 / Gemfan Hurricane 5.1x4.66x3 class),
X frame 225 mm motor-to-motor diagonal, AUW 0.61 kg. The closest published twin is Tal & Karaman's 609 g, 4S, 2400 KV, 5055-prop INDI quad.

## 2. How PX4 gz x500 encodes these quantities (read from the repo)

Files: `Tools/simulation/gz/models/x500_base/model.sdf` (body, rotors, joints), `Tools/simulation/gz/models/x500/model.sdf` (4 x `gz::sim::systems::MulticopterMotorModel` plugins, one per rotor), `ROMFS/px4fmu_common/init.d-posix/airframes/4001_gz_x500` (PX4 side).

Convention (gz MulticopterMotorModel): thrust = motorConstant * w^2; reaction moment = momentConstant * thrust (so kQ = momentConstant * motorConstant, momentConstant = kQ/kT [m]); first-order rotor speed with timeConstantUp (speeding up) / timeConstantDown (slowing); command clipped to maxRotVelocity; rotorDragCoefficient and rollingMomentCoefficient scale |w| times the body-frame velocity perpendicular to the rotor axis (drag force, rolling moment); `rotorVelocitySlowdownSim` (x500: 10) only slows the visual joint velocity.

## 3. Consistency checks

1. Thrust at hover: 4*kT*w_h^2 = m g. With kT = 1.5e-6 and w_h = 998.6 rad/s: 4*1.5e-6*998.6^2 = 5.98 N = 0.610*9.81 = 5.98 N. OK (by construction). With the hover-region kT = 1.25e-6: w_h = sqrt(5.98/(4*1.25e-6)) = 1094 rad/s = 10,450 rpm; MQTB 25% row (168 g at 11,002 rpm) scaled to 152.5 g gives 10,480 rpm. OK (0.3% difference).
2. Full-throttle thrust: 4*1.5e-6*2800^2 = 47.0 N vs MQTB 4 x 13.65 N = 54.6 N (1392 g/motor, 2550 KV, 2306.6) scaled by (2400/2550)^2 = 48.4 N. OK (3% difference). T/W = 7.9. Agilicious: 4 x 9.5 N continuous / 7.36 N weight = 5.2 (heavier platform with Jetson). The 610 g platform has ~50% more T/W than the 750 g research quads, as expected for a freestyle build.
3. kQ/kT: Kaufmann 0.01221 m vs chosen 0.01267 vs MQTB-power estimate 0.0107-0.0122 (eta 0.70-0.80) vs x500 0.016 (13-in prop). OK.
4. Yaw authority: max yaw torque (two motors at w_max, two at ~0) = 2*kQ*w_max^2 = 2*1.9e-8*2800^2 = 0.298 N m; /Izz 2.7e-3 = 110 rad/s^2 of angular acceleration at full-range differential. Roll authority (two motors on one side at w_max, the other two at ~0): 2*11.76*0.0795 = 1.87 N m; /Ixx 1.4e-3 = 1,340 rad/s^2. Torque-to-inertia of this order matches the "agile" 5-inch class (Agilicious frames agility by T/W and torque-to-inertia).
5. Time constant vs physics: spin-up from 0 to 2800 rad/s needs kinetic energy 0.5*5e-6*2800^2 = 19.6 J; with ~300-400 W available (MQTB 623 W electrical at 100%, motor torque limit Kt*I = 4.0e-3 N m/A x 40 A = 0.16 N m, rising to 0.24 N m at 60 A) a full-range step takes ~50-70 ms to complete, consistent with a first-order time constant of ~33 ms (63%) measured by NeuroBEM and 39 ms by Agilicious. Rotor inertia 5e-6 is therefore plausible; a J_r of 1e-5 would give >100 ms and contradict the measured time constants.
6. Mass check: component sum in section 1 row 2 (motors 132 g, props 18 g, frame arms 70 g + plates 40 g, stack 40 g, 4S battery 190 g, FPV 50 g, misc 70 g) = 610 g. Agilicious: frame 86 + motors 110 + props 20 + battery 199 + FC/ESC 21 = 436 g without the 154 g Jetson and wiring; the 610 g platform is plausible.
7. Quadratic-model error: kT varies by ~20% between hover and full speed (1.25e-6 to 1.54e-6, MQTB). Any INDI simulation should either use the chosen 1.5e-6 and accept a ~20% hover control-effectiveness error or use a speed-dependent kT; this is a deliberate mismatch source worth testing (INDI gain-robustness).
8. gz mapping check: gz thrust at hover command w = 998.6 rad/s with motorConstant 1.5e-6 gives 1.496 N/motor; four rotors 5.98 N. OK. For comparison the x500: 4*8.54858e-6*1000^2 = 34.2 N max, T/W = 1.74, hover w = 757 rad/s.
