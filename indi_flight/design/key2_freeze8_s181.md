## MINOR

m1 F2 applies in every mode, not only offboard. McIndiPosControl.cpp:1017 extrapolates whatever _setpoint holds. The spec (DECISIONS.md:1019) says "the offboard setpoint"; the probe flew offboard cruise_typ only. In auto/goto modes the setpoint is published at module rate, so dt is only the publish-to-use latency (ms): small but non-zero, and unflown. Either gate it or state "all modes" in the decision.
m2 Fallback path is not extrapolated. McIndiPosControl.cpp:1062,1069: _last_valid_setpoint = _setpoint (raw held sample), so the rare "update failed, retry within 200 ms" path re-feeds the staircase. Acceptable (failure path); note it.
m3 TRAJECTORY_STREAM_TIMEOUT_US (McIndiPosControl.hpp:308) is used nowhere else in the module, and no timeout is enforced; SetpointExtrapolation.hpp:6 and :23 call it "the stream timeout of the module". On a stale stream the setpoint is therefore held at the 0.5 s extrapolated point forever (velocity v + 0.5 a, position p + 0.5 v + 0.125 a), while acceleration feed-forward stays a. Continuous (no step at the cap), and the commander offboard-loss failsafe owns the real stale handling, but the comment overstates, and with a != 0 the capped v and a are mutually inconsistent. Pre-change the hold was v. Suggest comment fix only.
m4 Time base relies on _setpoint.timestamp being set by the sender in PX4 time. Code uses hrt_absolute_time() - sp.timestamp (SetpointExtrapolation.hpp:30-35, us, hrt_abstime on both sides, units correct). MAVLink receiver stamps on receipt (not verified in this pass), uXRCE-DDS relies on timesync. If a sender stamps a stale or offset clock, dt saturates at 0.5 s and every velocity-carrying setpoint is shifted by 0.5 v permanently. The existing check at McIndiPosControl.cpp:888 only rejects timestamps before position-control entry. A max-age sanity (e.g. treat dt > cap as "no extrapolation" instead of "cap") would bound this; currently cap = still extrapolate 0.5 s.
m5 Yaw/yawspeed are not extrapolated (deliberate, matches spec p/v only); jerk ignored. Fine, listed for completeness.

## OK

OK1 Extrapolation function, SetpointExtrapolation.hpp:23-56. Pure, copy semantics (_setpoint stays raw: it is still used for 888/896/955/1021/1091 and the held-sample logic). now <= timestamp returns unchanged (also covers timestamp in the future, and unsigned underflow is avoided because the compare is first). dt cap applied in integer us before float conversion. NaN rules: velocity NaN leaves the axis untouched; position only moved with finite velocity; acceleration term only when finite; NaN a keeps NaN a in out. First sample: timestamp > 0, dt small. Empty setpoint (timestamp 0, all NaN): no-op. Failsafe setpoints (FailsafeSetpoint.hpp: v=0 with NaN p/a, or a=0 with v=land_speed): extrapolation is a no-op or identity. Ground/not-taken-off setpoint (CPP:961): velocity NaN, no-op. Takeoff ramp: a[2] set NaN at CPP:956 before extrapolation, so no ramp distortion.
OK2 Jump / long gap: a new sample replaces _setpoint in full each update (CPP:869) so the extrapolation restarts from the new sample; no extrapolation across a jump. A long gap is capped at 0.5 s (see m3, m4). Mode exit clears _setpoint to empty (CPP:830); mode entry uses the timestamp >= enable-time gate (CPP:888-896). EKF resets: adjustSetpointForEKFResets runs on the raw sample before extrapolation (CPP:871), so the shift is carried through correctly.
OK3 Lead filter F4. indi_rate_control.cpp:399-404: alpha = dt/(Tc + dt) is backward-Euler, exact for variable dt (alpha follows dt each call), Tc in seconds (0.03f, header:279), dt validated to [0.125 ms, 20 ms] and finite at :231, so raw = diff/dt cannot see a tiny dt. Reset: _sp_lead_reset and landed zero the state (:394), and _rate_sp_prev follows the setpoint (:408). Feed-forward only: _rate_sp_dot enters only the numerator at :458 as lead_gain * r_dot and is exported to the status topic; it does not enter rate_error, a_f or t_f. Single-line constant change, no other code touched.
  Caveat (not a defect): the slower filter delays the lead by about 20 ms more for real manoeuvres. The spec acknowledges G2-STEP and G5.5 tracking are not yet checked (DECISIONS.md:1062); that is the re-fly list.
