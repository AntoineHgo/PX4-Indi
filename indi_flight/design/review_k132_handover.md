# K132 second-key review: D-HANDOVER (code to specification)
Read-only review, nothing built or run. Files: HandoverBlend.hpp, HandoverBlendTest.cpp, McIndiPosControl.cpp (runIndiStage, caller 955-1015), lib/indi_accel_control/indi_accel_control.cpp (reset, jerk diff, z_only).

## 1. Specification match: OK
- bypass(a_c_pre_inject) is called in the bypass branch after Hold/can_run exits. a_c_pre_inject = local_pos_sp.acceleration read after _control.update(); in bypass want_indi is false or the stage is not active, so the stock integrator was not reset that cycle (resetIntegral at 972 only if want_indi; at 1012 only if _indi_active). Integrator is included.
- apply() captures on the first can_run cycle (pending flag), then multiplies the offset by exp(-dt/tau). Not an integrator: no error input, fixed decay. A later a_ref step is not absorbed (offset is not recomputed). All three axes. Non-finite: a_bypass or a_ref non-finite gives zero offset; non-finite or non-positive dt skips decay.
- First cycle output equals a_bypass exactly (no decay on the capture cycle). OK.

## 2. Paths
- Hold between bypass and first INDI cycle, Hold chosen by selectStageMode (stale attitude/acc, rate): bypass() is not called, pending stays true, a_bypass is the last bypass value (possibly old). Capture happens at the first can_run cycle against that old value. For a short hold this is what is wanted (the integrator is still the one zeroed). Long hold: the bypass value is stale, but the stock integrator also keeps no history, so a_bypass vs a_ref still gives a continuous a_ref. MINOR (acceptable).
- Hold caused by _indi.update() rejecting (dt outside kMinDt..kMaxDt, bad q): apply() already ran and consumed pending, so capture is done and decays through the hold only on cycles that reach apply. Fine. OK.
- Hold after the offset was captured (Indi -> selectStageMode Hold -> Indi): decay runs only in apply(), i.e. in cycles, not in wall time. Offset is frozen during the hold and resumes at the residual. MINOR (a hold is short; decaying with wall time would be cleaner).
- Same freeze when the module leaves position control (the caller else-branch, line 1025, does not call runIndiStage): switch to manual 0.1 s after take-off at o=2.2, return in flight 20 s later, offset resumes at 2.2 added to a_ref with no bypass in between. MAJOR-ish edge for flight (within about 2 s of the bypass->INDI edge only); suggest clearing the offset when the stage is not run for more than a cycle (call a reset/invalidate from the else branch or from Hold-by-selectStageMode after some time).
- T10 estimator reset (_indi_reset_pending): does not re-arm the capture and does not touch the offset. Reset clears the library jerk history, offset keeps decaying. OK. (If the reset coincides with the first cycle: capture first, reset after, harmless.)
- Loop-break injection: inject only in StageMode::Indi, added after the handover (a_ref = a_c_hand + inject), PINJ_PT=1 uses a_c_hand. The bypass value never contains injection. OK. Side effect: for 2 s after a take-off handover c is not the stock c; status.a_c_pre_inject logs the stock value, not the offset one, so identification data in that window have an unlogged additive term (the offset is only visible in status.a_c). MINOR: log it or exclude the window.
- z-only (ALTCTL): a_c_pre_inject must still be all finite (aref_ok), so the capture is consistent. Only a_ref(2) feeds the collective; xy offsets are carried but unused; omega_ff off in z_only. OK. Not verified: that xy of local_pos_sp.acceleration is finite in ALTCTL (if NaN, there is no stage run at all, so no change in behaviour).
- Disarm / re-arm: disarm leaves the position-control branch; pending/offset keep their values. Re-arm starts landed, every cycle is bypass and overwrites a_bypass, pending = true. OK. Residual offset from a flight is overwritten by the next capture (the capture assigns, does not add). OK.
- Bypass cycle with non-finite acceleration: bypass() sets pending=false and keeps the OLD a_bypass and the OLD offset. Next stage cycle then does no capture and keeps decaying a previous offset (stale from an earlier handover) while the real step is not blended. Can this occur? aref_ok false normally selects Hold, not Bypass, so it is likely unreachable (selectStageMode not read: NOT VERIFIED). MINOR; fix is to zero _offset in bypass() when non-finite.
- Long bypass: a_bypass is overwritten every cycle, the last value counts. OK.

## 3. Interaction with the library: OK
- reset() (bypass branch, every cycle) invalidates _a_ref_prev, so the first stage cycle seeds the history and gives no jerk; the capture cycle is continuous. After that j_diff = d(a_ref)/dt includes -o/tau (about 5.3 m/s^3 on z at 2.67). That is the true derivative of the commanded a_ref, so feed-forward is consistent; clamped to kMaxJerk; for xy it goes through omega_ff, which is the intended behaviour. The "unchanged value holds last difference" logic is unaffected (offset changes every cycle). Not harmful. Per-cycle exponential steps with the 1/dt_change differencing give a smooth jerk; not simulated.
- thrust_dir (z_only) is the stock thrust, not offset; only used for direction and the gate. OK.

## 4. Tests
- FirstStageCycleIsContinuous: catches capture removed, wrong sign, axis dropped (3 axes checked). OffsetDecaysWithTau: catches no-decay, wrong tau, decay applied on the capture cycle (0.1 s window 17-19 %). NoBypassNoOffset, CapturedOnceOnly (catches re-capture on every cycle / absorbing a later step; checks the decay factor), NonFinite (catches NaN propagation both ways), DisabledByTau.
- Untested and relevant: (a) integration/caller wiring (bypass() placement, apply() before inject, a_ref used by the library) is not covered by any test: moving the bypass() call, or applying the offset after the inject, passes all 6 tests; (b) bypass(non-finite) after a previous offset (stale offset above); (c) frozen offset over a gap / long-gap reset; (d) bypass() twice then apply (last wins); (e) dt <= 0 or NaN dt on a decay cycle; (f) the "a later step is not absorbed" test uses small dt only; (g) recapture while a residual offset exists (assignment, not accumulation).
- Not verified: the break check (3 failing tests) was taken from the brief; the tests were not compiled by me. CMake line added correctly for a header-only test (no LINKLIBS needed).
