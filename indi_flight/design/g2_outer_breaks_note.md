# G2 outer-loop breaks: attitude, velocity, position, INDI acceleration

Status: design note, no firmware written. "V" = read in source this session (file:line). Everything else is UNVERIFIED and listed in section 8.

## 0. Rules and lessons
- G2 (MISSION.md): L identified by injection at each break, cross-checked against a linear model; GM >= 6 dB, PM >= 45 deg, delay margin >= 2 control periods + telemetry latency, at 400 and 800 Hz. Here "control period" for an outer break is that loop's own period (outer cycle), UNVERIFIED reading of the gate; confirm with the owner.
- O-11: mc_rate_control, mc_att_control, mc_pos_control, control_allocator, allocation lib, commander: zero diff. Their only reachable interfaces are uORB topics.
- S36: each break names every path it cuts. S41: the model holds every loop the break closes. S43: pretest measures each chain link (rates, latencies, gains) on the log before any derived gain is used.
- Convention: additive break u = c + d, x = u (what the plant sees), c = returned signal, L = -G_yd/G_xd (as `bench/margins_est.py`, M3a). Because c = x - d, one logged x plus the known d suffices; log c as well as a check.

## 1. Stock PID chain and the O-11 constraint (V)
trajectory_setpoint -> PositionControl: `_vel_sp` = trajectory vel + P*(pos_sp-pos) (PositionControl.cpp:130-134, NaN terms drop out); `_acc_sp` = trajectory acc + [Kp e_v + I - D*vel_dot] (:150-153) -> thrust vector/q_d -> vehicle_attitude_setpoint (MulticopterPositionControl.cpp:643) -> mc_att_control (consumes q_d :338, P law, publishes vehicle_rates_setpoint :389) -> mc_rate_control. mc_pos_control runs on a vehicle_local_position callback, dt clamped to [2, 40] ms (:64, :390); mc_att_control runs on a vehicle_attitude callback (mc_att_control_main.cpp:83). The stock modules publish vehicle_local_position_setpoint with the final `vx,vy,vz` and `acceleration` (PositionControl.cpp:255-266).
Key fact: the trajectory_setpoint velocity and acceleration fields are ADDED to the loop's own terms (:133, :153). So a bench injector publishing trajectory_setpoint in offboard reaches true additive breaks at the velocity-setpoint and acceleration-setpoint sums with no stock edit. Attitude has no additive input: q_d is replaced, not summed.
Rejected: a second publisher writing vehicle_attitude_setpoint / vehicle_rates_setpoint / vehicle_torque_setpoint next to the stock module (race, last writer wins, no defined sum); stopping a stock module and re-implementing it (no longer the stock stack).
Recommended PID injector: one new bench-only module (e.g. `src/modules/g2_inject`, not on the O-11 list, not in default builds) or the existing ROS-less Python offboard path in `indi_flight/bench` (UNVERIFIED which exists), publishing trajectory_setpoint (and, for the attitude break, vehicle_attitude_setpoint in a mode where mc_pos_control is idle). It logs d itself through the setpoint it publishes (no new msg). Same injector serves the INDI stack for the reference-type breaks, so PID and INDI are compared with identical excitation.

## 2. Attitude break
1. Injection. PID: reference injection, d added to q_d roll/pitch angle in vehicle_attitude_setpoint published by the injector, offboard attitude mode, mc_pos_control idle; thrust held by the injector (slow altitude PI < 0.1 Hz, outside the band). L_att = T/(1-T), T = roll/(roll_d) (unity feedback, yaw_sp_move_rate = 0). INDI: additive u = c + d on the rate setpoint in `McIndiPosControl.cpp:571` (`rates = constrain(att.update(q) + omega_ff)`), before `publishRates` (:583); params `MC_INDIP_INJ_*` (new, follow MC_INDI_INJ_* pattern).
2. Logged. PID: x = vehicle_attitude_setpoint.q_d (injector rate), y = vehicle_attitude.q (attitude rate; UNVERIFIED rate, measure) ; also vehicle_angular_velocity. INDI: x = vehicle_rates_setpoint (c+d), c = new field in indi_pos_status (att P output before d); y returned = c.
3. Paths cut. PID reference break: nothing cut, the loop is closed through rate PID + plant; outer loops are open (offboard attitude mode) so they are NOT in L. INDI additive break at rates setpoint cuts the attitude P path (q -> c) AND the path through q_d (a_f -> t_c -> q_d -> c, via the accel, velocity and position loops): L here is the total multi-loop gain, so the model must contain all (S36, S41).
4. Model. PID: L = K_att(MC_ROLL_P/MC_PITCH_P) * F_q(s) * T_rate(s)/s with T_rate = closed rate loop (MC_ROLLRATE_P/I/D, MC_ROLLRATE_K, filters, motor lag, delay), F_q = attitude-estimate lag/delay (EKF2 output delay + hold). INDI: section 6.
5. Work. PID: injector + attitude-offboard mode check (UNVERIFIED commander accepts it in SITL). INDI: ~30 lines in McIndiPosControl (inject, log c); fault path asserts as in M3a. Zero stock diff.
6. Band 0.5-15 Hz (rate crossover ~3.5 Hz measured for INDI roll; keep >= 4x below the Nyquist of the loop). Amplitude 0.5-1 deg RMS roll, flat in |d| over bins, SNR check in pretest.
7. Risks. INDI attitude P may run at the sensor_combined rate, not the pos rate (UNVERIFIED; module registers both callbacks, :64, runCycle at :632): measure vehicle_rates_setpoint rate first. A PID att-only L differs from the INDI total L by construction; compare PID att-only with the INDI model evaluated with outer gains zero (section 6 check).

## 3. Velocity break
1. Injection. PID: additive d on trajectory_setpoint.velocity with pos_sp finite and held (summed at PositionControl.cpp:133), i.e. a cut at the position-P output. INDI: additive d on v_sp after `p_term + v_ff` (indi_accel_control.cpp:243), before the clamp/a_c at :257.
2. Logged. x = vehicle_local_position_setpoint.vx,vy (PID, V :258-260, final after limiting, mc_pos_control rate) / new indi_pos_status field v_sp+d (INDI); y returned c = x - d (c = P(pos_sp-pos) + v_ff). Plus vehicle_local_position (v, ~88.9 Hz).
3. Paths cut. The cut at the v_sp sum returns the position loop only: c = K_pos*(p_ref - p), p = int v. So L_v-break = (K_pos/s) * T_v(s), T_v = velocity loop closed (velocity PID/INDI accel + attitude + rate), the quantity the position-loop margin is made of. The velocity loop itself is seen at the acceleration break (section 5). Name this in the result table as "position-P output cut", not "velocity loop".
4. Model. T_v = L_v0/(1+L_v0), L_v0 = K_v(s) T_a(s)/s. PID K_v = MPC_XY_VEL_P_ACC + MPC_XY_VEL_I_ACC/s + MPC_XY_VEL_D_ACC*s*LP(MPC_VELD_LP) (D acts on filtered vel_dot, V :150, mc_pos_control.cpp:336); INDI K_v = lib `_k_vel` (default 1.8, hpp:177; mapping to MPC_XY_VEL_P_ACC UNVERIFIED). T_a = a/a_sp: tilt = a/g (:217), attitude loop (section 2) and rate loop. Add velocity-estimate lag F_v (EKF) and one-cycle delay.
5. Work. PID: injector only. INDI: ~15 lines in the lib input path (inject, expose v_sp_used in Output; lib unit test IndiAccelControlTest).
6. Band 0.2-5 Hz. Amplitude 0.2 m/s RMS.
7. Risks. constrainXY prioritises the position component over the feed-forward (V :139): a large d is clipped, keep d far below MPC_XY_VEL_MAX. D term makes PID L noisy above ~5 Hz.

## 4. Position break
1. Injection. Reference injection on trajectory_setpoint.position (both stacks, same injector), velocity/acceleration fields NaN, INDI `MC_INDIP_FF` = 0 so no feed-forward bypasses the loop (NaN handling in the lib UNVERIFIED).
2. Logged. x = trajectory_setpoint.position (+ d, injector rate); y = vehicle_local_position x,y,z (~88.9 Hz, measured in the S35 era, UNVERIFIED for 400 Hz); T = y/x, L_pos = T/(1-T).
3. Paths cut. None cut (reference break); closed around it: position P, velocity loop, attitude, rate. L_pos = (K_pos/s) T_v; margin of record = the minimum over the T/(1-T) estimate; numerically poor where |T| ~ 1, so read PM/GM only near the crossover (about 0.5-1.5 Hz expected, UNVERIFIED).
4. Model. K_pos = MPC_XY_P (0.95 default INDI lib, hpp:176, PID default per params yaml UNVERIFIED), T_v of section 3, F_p position-estimate lag. z separately: MPC_Z_P, MPC_Z_VEL_P_ACC, hover thrust, thrust-path T_z.
5. Work. PID and INDI: injector only. 6. Band 0.1-2 Hz, amplitude 0.2 m RMS horizontal, 0.1 m vertical.
7. Risks. Low-frequency bins need long records: T_p 9 s, >= 6 periods.

## 5. INDI acceleration break (M3b) and its PID twin
1. Injection. INDI: d added to t_c immediately after `Vector3f t_c = t_f + (a_c - a_f)` (indi_accel_control.cpp:273, V), BEFORE the saturation (:283-318), `c` (:297), `thrust = constrain(c/(g_t k_cmd))` (:322), q_d (:326), omega_ff, `_thrust_prev = thrust` (:345, V; it feeds the fallback `u_in = _thrust_prev*k_cmd` at ~:263 when the ESC mean_u is invalid). Hence publish and every store inherit d from one place. Per axis d_x,d_y,d_z, one axis per run. The M3b rule of S35 sec. 7 is thereby satisfied; the S38 line-number record is this paragraph. PID twin: additive d on trajectory_setpoint.acceleration (summed at PositionControl.cpp:153); PID has no thrust-vector store.
2. Logged. INDI: x = t_c + d (new status field `t_c_inj`; existing `t_c` at McIndiPosControl.cpp:444 is pre- or post-injection by design, name it), c = t_c pre-injection (new field), plus a_c, a_f, t_f (existing). PID: x = vehicle_local_position_setpoint.acceleration (V :265), y = c = x - d; measured a: vehicle_local_position ax,ay or sensor_combined (V that the lib uses sensor_combined, hpp comment) at the outer rate. Rate: indi_pos_status ~ outer rate (UNVERIFIED), PID setpoint at mc_pos_control rate.
3. Paths cut (INDI, by t_c): (i) thrust-measurement path ESC mean_u -> u_f -> t_f (via delay MC_INDIP_DLY, LPF MC_INDIP_LPF_CUT) at the t_f in the next cycle; (ii) accelerometer path f_b -> LPF -> R f -> a_f; (iii) attitude-estimate path q -> z_b -> t_f and R -> a_f; (iv) via a_c: velocity and position P (K_v(v_sp-v), v_sp = K_p(p_ref-p)). It closes around: INDI rate loop, attitude P (module-owned copy of MC_ROLL_P, McIndiPosControl.hpp:202/239, V), thrust loop, translational dynamics, and the position/velocity loops. Total L = all of these; the INDI inner effect is the (t_f - a_f) term.
4. Model (small angle, per axis, outer rate sampled): c = (t_f - a_f) + K_v(1 + K_p/s)(-v) ; v = T_a a/s ... L_a = [E(s) - F_a(s)] G_tilt(s) + K_v(1+K_p/s) T_a(s)/s, with E = thrust-measurement chain (motor lag, delay_samples, LPF_u), F_a = accelerometer chain (LPF_f, sensor/EKF delay), G_tilt = attitude loop + rate loop closed, T_a = a/a_c. Self-tests: (a) E = F_a gives L_a = K_v(1+K_p/s)T_a/s (pure outer PD); (b) K_v=K_p=0 gives the pure INDI-increment loop; (c) PID twin: L_acc = K_v(1+K_p/s) T_a/s with PID gains from the PID block list of section 3. T_a is measured, not derived (S43): the pretest logs a_c -> a (step in a_ref) before trusting G_tilt.
5. Work. INDI: add `Injection` member in the lib (same parameter block as IndiInjection), 3-axis multisine, two status fields, one unit test (fault == 0, d flows to thrust and _thrust_prev). PID: injector only.
6. Band 0.3-10 Hz INDI (outer Nyquist 44 Hz, lib LPF 10 Hz), amplitude 0.2 m/s^2 RMS (~1.2 deg tilt). 7. Risks: ESC window averaging (closeInputWindow, V) adds a half-cycle skew, kept in the model as in S38 (O(T) term); the d_z axis moves thrust and can hit the thrust clamp (:322).

## 6. Linear model that closes A-26 (roll M3a, outer loops closed)
c = K_att(MC_ROLL_P)[theta_d - F_q theta]; theta = (T_w(s)/s)(c + d) with T_w the closed INDI rate loop (existing S37/S48 model). theta_d = a_c-path: a_c = -K_v(1+K_p/s) v + (t_f - a_f) increment, v = G_a(s) theta with G_a = (g/s)(drag/blocked) [x: roll -> y-accel sign fixed by self-test], F_q = estimator attitude lag+delay. Result: L_roll = (T_w/s) K_att [F_q + H_out(s)], H_out = (1/g)[K_v(1+K_p/s) g/s * T_{E/F}(s)] (signs to be fixed by the self-tests). Requirements: (1) outer gains = 0 and F_q = 1 reproduces S48 exactly; (2) gains = MPC values: the 1-2 Hz bins agree within 5 deg (A-26 test). Everything in the model comes from params (MC_ROLL_P, MPC_XY_P, MPC_XY_VEL_P_ACC) or logged chain measurements (F_q from vehicle_attitude vs ground truth, S43).

## 7. Multisine design and ordering
Rates: outer ~88.9 Hz (= 800/9 observed in logs, UNVERIFIED), controller 800, 400, 800/3 Hz. T_p = 9.000 s: 7200, 3600, 2400, 800 samples at 800, 400, 800/3, 800/9 Hz (and 1125 at 125 Hz): all whole. f0 = 1/9 Hz; odd bins k only, Schroeder phases, d held ZOH per outer cycle; discard the first period; >= 6 periods (54 s); `frf_periodic` per bin. Do not assume the outer rate at 400 Hz: pretest logs it.
Implementation order (sessions): S-a pretest: measure the topic rates and chain links (att rate, local position rate, T_a step, F_q) at 400 and 800 Hz, decide the injector home (1); S-b PID injector module + acceleration, velocity breaks flown, PID model (1-2); S-c position and attitude PID, A-26 model update with outer loops, closing test (1-2); S-d INDI lib/module injection (M3b, velocity, attitude) with unit test (1-2); S-e INDI flights at 400/800 Hz, cross-check, margins table (1-2). Total about 6-9 sessions.
