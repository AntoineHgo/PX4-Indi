# K130b second key: f_b_valid=false model substitution (read-only review, not built or run)

Verdict: no BLOCKING.
- MINOR (indi_accel_control.cpp:325-331): t_f = lpf_u(u)+b (b added after the filter), f_b = lpf_f(u+b) (b added before). LowPass2p is linear with unit DC gain, so the two are equal for a held b once both filter states are consistent. b is frozen when f_b is invalid (blend_frozen, :337-338). Delay index i_d, `_tb>0` condition, `_g_t` and R/z_b are identical. setFilter (:78-80) sets the same cut-off and rate on lpf_f and lpf_u. One residual: at the valid->invalid edge lpf_f still holds real accelerometer history, while lpf_u holds the actuator history. This gives a bounded transient of about one filter time constant. It is untested, because the tests start from reset().
- Default path: OK. With f_b_valid true, u_valid == mean_u_valid and f_in == in.f_b. lpf_f and the delay line share no state, so moving the f_b filter after the delay line has no effect. u_sub is computed but unused (harmless). The input guard at :237 is unchanged when valid.
- MAJOR (IndiAccelControlTest.cpp, test 2 `InvalidFbStepInARefIsBounded`): the bound `peak < kG+4` is loose, and the final NEAR is a steady-state check where delayed and undelayed substitution agree. This test would very likely pass with an undelayed substitution, so it does not assert the spec. Test 1 (`...WithDelay`, max_err < 0.05 over the transient from hover to a_ref=(0.5,0,-1)) should fail with an undelayed substitution, but I did not run it. Suggest a test that compares t_c against a_ref-g sample by sample during a ramp in a_ref, and a valid->invalid->valid switch test. There is also no bit-identical default test.
- Module hysteresis (McIndiPosControl.cpp:196-210): latch on any stale or non-finite sample, release after 20 ms (kAccRecoverTime, .hpp:139) of continuous fresh acceleration. It is correct. MINOR: if runIndiStage is not called for a long time while `_acc_fresh_since` is non-zero, it could unlatch instantly. Check the call cadence in the grep output above.
- Injection (.cpp:232): gated by `mode == StageMode::Indi`, so it is zero in IndiModelAccel. OK. The mode-to-library mapping is correct: f_b_valid = !model_acc, mean_u_valid = fresh_esc && !model_acc, and blend_hold also holds under model_acc (redundant with the library freeze, harmless).
