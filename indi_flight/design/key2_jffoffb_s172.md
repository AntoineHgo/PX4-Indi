# Key2 review D-JFF-OFFB (S172), code vs spec

Verdict: spec met. No BLOCKING. One MAJOR-to-MINOR edge item, one MINOR.

(1) Ordering: _vehicle_control_mode is copied at McIndiPosControl.cpp:812-815, in the local-position update, before runIndiStage and the setFeedforward call (:323). The flag is set only in the OFFBOARD nav-state branch of modules/commander/ModeUtil/control_mode.cpp:113 (MAVLink offboard). OK.
(2) The only other setFeedforward call is the constructor, McIndiPosControl.cpp:57 (true). Nothing in parameter updates or resetStageState touches _jerk_ff. The per-cycle call sits inside the stage-run block. When the stage does not run (ground, ramp), the flag keeps its last value, but the library is not called then. OK.
(3) Library: _jerk_ff is read only at indi_accel_control.cpp:440. With it false, omega_ff stays zero-initialised, and thrust, q_d and a_c do not use it. updateJerkDifference (:291, :156) runs unconditionally before it, so history and LPF keep running in all modes. OK.
  Edge into offboard: j_used = _j_diff_f, the LPF output of the held difference (hold 0.1 s, kJerkHold). The first offboard omega_ff is therefore j_diff_f/c at once, with no ramp, up to kMaxOmegaFf=3 rad/s. The jerk is not stale beyond 0.1 s plus the LPF tail. The cycle at which offboard a_ff replaces the stock a_ff gives one difference of step/dt_change, clamped to +-50, then filtered.
  Before this change the same j_diff_f was already feeding omega_ff on that edge, so there was no step in omega_ff, only the a_ff step. Now there is an omega_ff step 0 -> j_diff_f/c at the edge, on top of the a_ff step.
  MINOR (MAJOR if the G4 re-fly shows a spike at the switch): indi_accel_control.cpp:440 / McIndiPosControl.cpp:323. Mitigation: on a rising offboard edge, call resetJerkHistory() or ramp omega_ff over about 0.2 s. This is not required by the spec. Not tested: no unit test covers the switch edge (IndiAccelControlTest.cpp:584-587 only toggles).
(4) The omega_ff publication is unchanged: valid is computed at McIndiPosControl.cpp:354 and does not depend on the flag. Outside offboard the message is valid=true with omega_ff=(0,0,..). The gate (IndiRateFeedforwardGate.cpp:39) is unchanged, so omega_ff_on is the same as before. The sp_source bit 5 (McIndiRateControl.cpp:404) does not flip at mode switches, so resetSetpointLead is not triggered. A zero omega_ff adds 0 at McIndiRateControl.cpp:250, with no change in validity or timeout behaviour. OK.
MINOR: the comment at :321 says a_ff follows the vehicle in auto modes; this is an assumption, and the S172 hover logs only support it for hover. Not verified for auto missions.
