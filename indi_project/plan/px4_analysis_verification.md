## Discrepancies and corrections (summary)

1. Line numbers for `MulticopterRateControl.cpp` in R and I refer to main and are right; the working tree of `feat/indi-control` has shifted lines (the PID call is at `:294` on the branch, `:229` on main). The chapter cites main.
2. Row 54 (I 1.5): the claim that unallocated control "does not include the slew-rate effect" is wrong. The allocator applies the slew limit to `_actuator_sp` before clipping (`CA:454-458`) and builds `allocated_control` from that setpoint (`ControlAllocation.hpp:146-153`), so an active slew limit does appear in `unallocated_torque`. Slew limiting is off by default (`_has_slew_rate` only when a slew param is set), so it does not matter for the x500.
3. Row 38 (I 2.2, 4.5): open question "does SIH `_u` include lag" is answered: yes, a first-order lag with `SIH_T_TAU` (`sih.cpp:481`). SIH is therefore the one simulator in this tree whose `esc_status` carries a modelled (lagged) quantity, with rpm = rpm_max * sqrt(u), not an echo.
4. Row 33: the active desaturation mode is decided by `MC_AIRMODE`, default 0 (disabled), a fact missing from both notes (the notes describe all three modes but never give the default). With the default, roll/pitch are scaled down before yaw is added, and yaw is desaturated last.
5. Row 13: the attitude controller on this main includes a second-order reference model with feed-forward of its rate (`AttitudeControl.cpp:94-137, 197-208`). Neither note mentions it; the chapter does, briefly, because it shapes the rate setpoint seen by the rate loop (it is not an acceleration setpoint).
6. Rows 50-51 were not re-checked (not load-bearing for chapter 4).
7. R's description of the unused part of `vehicle_angular_velocity` timestamps, R's group-delay estimates (5.6 ms, 8.0 ms, 13.6 ms) and the claim that the sensor filters run at kHz in SITL are analytic or unmeasured and were not re-derived here; the chapter labels them as estimates.
